## 🎯 What Makes CampusConnect v2 Unique?

CampusConnect v2 serves two complementary purposes:

### 1. Student Support & Academics Portal
* **8 Core Computer Science Subjects:** Machine Learning (`CSE601`), Computer Networks (`CNT501`), DAA (`CSE602`), Cloud Computing (`CSE603`), DSA (`CSE604`), OOPs (`CSE605`), DBMS (`CSE606`), and Advanced DS (`CSE607`).
* **Complete Subject Resources:** 8-unit syllabus breakdown, weekly timetables with lab slots, curated YouTube playlists (🎬), reference textbook PDFs (📚), real-time class chat, and interactive assignments with submission tracking.
* **Support Ticketing:** End-to-end helpdesk with priority triage, status tracking (`OPEN` → `IN_PROGRESS` → `RESOLVED`), and student-admin conversation threads.
* **AI Knowledge Assistant:** Grounded campus helpdesk query engine with local markdown retrieval and safety guardrails.

### 2. CNT (Computer Networks & Telecommunications) Research Core
* **Fault Localization under Informative Missingness (M1):** Fuses human complaints with topology adjacency and telemetry. When an access point crashes, it goes silent — the localizer treats *silence as evidence*, achieving **+34 pp accuracy over telemetry-only baselines** at 20% blind nodes.
* **Protocol v2 Reliable Delivery:** Cryptographically signed HMAC-SHA256 datagrams with correlated ACKs. Solves burst packet loss using **scheduled spaced copies with cancel-on-ACK**.
* **Sliding Anti-Replay Window:** 64-entry bitmask window (RFC 4303 concept) that safely accepts out-of-order UDP datagrams while rejecting replays.
* **Length-Prefixed TCP Framing:** Solves byte-stream multi-byte character boundary corruption.
* **CNT Visual Lab (`/lab`):** Interactive simulations of Gilbert–Elliott burst loss, RFC 6298 adaptive RTO timers, replay windows, and OSI layer mappings.

## 🔬 Honest Research Disclosures
* **Synthetic Data Testbed:** All 97 network nodes and incident scenarios are evaluated against calibrated synthetic generators (`topology/campus.yaml`). The +34 pp localizer gain is measured on this generator. An independent 38-node generator (`experiments/independent_eval.py`) with Pareto tickets and Student-t noise replicates 95.9% Top-1, reducing (but not eliminating) circularity. Real SNMP/Syslog collection would be the next validation step.
* **Benign Surge False Positives:** Without the surge guard, the localizer flags ~51% of high-volume benign crowd surges as hardware faults. The multi-condition heuristic guard (`check_operational_surge` in `ml-service/src/localize_api.py`) reduces this by suppressing incidents when upstream switches are healthy, LINK-symptom fraction is low, and no peer APs are catastrophically failing. The guard catches ~55% of surge scenarios; residual false alarms remain.
* **Conformal Coverage Caveat:** The conformal guarantee (LAC / Mondrian) is marginal and assumes exchangeability. Coverage degrades under Missing-Not-At-Random (MNAR) failures — the exact regime where failing nodes go silent. The `experiments/e3_localizer.py` output reports realized coverage, not the theoretical 1-α level.
* **tc netem Benchmark:** The spaced UDP copy experiment (`experiments/netem_test.py`) runs in WSL2 with virtual network namespaces, not on bare-metal hardware. The routing uses a veth pair with `tc netem loss 20% 50% delay 40ms`. Results (spaced 99.7% vs back-to-back 97.3% at a 140 ms deadline) are indicative but not equivalent to a physical multi-NIC test.
* **Adaptive Timers:** Offline evaluation (E5) demonstrated that Q-RTO beat RFC 6298 in 5/6 scenarios, but did not outperform a simple empirical quantile timer; production safely retains RFC 6298.
* **Academics Portal scope:** Subject resources (syllabi, YouTube playlists, textbook links) are static-seeded demo content. The portal demonstrates the UI concept and overlaps in function with Moodle or Google Classroom. It is demo scaffolding supporting the thesis, not a production LMS replacement.

## 🔐 Security Notes & Known Gaps

> [!WARNING]
> The following items are **known limitations** acknowledged for the academic prototype scope.

| Gap | Current State | Recommended Fix |
|---|---|---|
| **HMAC key rotation** | Single static key (`PROTOCOL_KEY_ID=k1`) in `.env`. No rotation mechanism. | Implement key-id versioned key ring; allow receiver to accept `k1` and `k2` during transition. |
| **Rate limiting** | No request-rate limit on `/api/v1/localize` or `/api/v1/network/inject-fault`. | Add `express-rate-limit` middleware (e.g. 60 req/min per IP) on all gateway routes. |
| **Location-tagged ticket privacy** | Building/room location is stored and exposed in `/api/v1/tickets` without anonymization. | Strip sub-room granularity before storage; use coarse zone tags only in API responses. |
| **Admin seed password** | The seed password is now in `.env` only, not in source. | Rotate before any shared deployment. Never push `.env` to version control. |
| **WebSocket auth** | Token passed as query param on Socket.io handshake (exposed in server logs). | Use `auth` object (`socket.handshake.auth.token`) and strip from logs. |
